# **🤖Chatbot**

**“텍스트 → 의미 분석 → 답변 생성”**

> 🎙️ 음성입력 (STT)  
↓  
📄 텍스트 ("모나리자는 누가 그렸어?")  
↓  
🧠 자연어 처리 파이프라인 (LangChain)  
├─ ① Intent 분석 ("작가 질문")  
├─ ② Entity 추출 ("모나리자")  
├─ ③ 지식 검색 (DB / 웹 검색)  
├─ ④ 답변 생성 (LLM)  
↓  
🗣️ TTS 변환 → 음성 출력
> 

---

### **음성(Client) → 텍스트(App)**

1. 음성 녹음, 파일 생성
2. 백엔드 API ‘/stt’
3. STT 모델 실행
4. 텍스트 결과 반환
5. 챗봇 로직 연동

## **챗봇**

### ① Intent(의도) 분석

user가 질문한 유형 분류

- “누가 그렸나요?” → artist_info
- “언제 만들어졌나요?” → year_info

| 방법 | 설명 | 예시 |
| --- | --- | --- |
| **규칙 기반** | 특정 단어 포함 여부로 구분 | “누가” → `artist_info` |
| **ML 기반** | Intent 분류 모델 학습 | BERT fine-tuning |
| **LLM 기반** | GPT 등에게 자연어 프롬프트 | `"이 문장의 의도를 한 단어로 분류해줘"` |

### ② Entity(개체) 추출

질문에서 핵심 단어(작품 제목, 작가 이름, 시대 등) 뽑는 단계

- “모나리자는 누가 그렸어?” → “모나리자”

- **분석 방식**
    
    | 방식 | 설명 | 장점 | 단점 |
    | --- | --- | --- | --- |
    | **LangChain (LLM 자동 분석형)** | LangChain Agent가 문맥으로 직접 의도 파악 | 구조 간단, Agent가 자동 선택 | 세밀한 제어 어려움 |
    | <span style="background-color: #b6d3f6;">**Intent/Entity 체인 분리형**</span> | 분석을 먼저 수행한 뒤 DB 선택 | 정확도 높음, 제어 용이 | 구조 조금 복잡 |
    
    - LLM 자동 분석 `initialize_agent()`
    - Intent/Entity chain 분리
        1. Intent + Entity 분석 chain 생성
        2. 결과 기반 DB Tool 선택

### ③ 지식 검색 (Retrieval, RAG)

Intent&Entity 기반으로 DB에서 관련 문서 검색 ([RAG 참고](https://proceedings.neurips.cc/paper/2020/file/6b493230205f780e1bc26945df7481e5-Paper.pdf))

| 구분 | DB 기반 | 웹 검색 기반 |
| --- | --- | --- |
| **방법** | 자료 직접 구축 | 검색 API 통해 실시간 |
| **정확도** | 높음 | 중간~낮음 (출처 다양) |
| **속도** | 빠름 (안정적) | 느림 (API 호출) |
| **유지보수** | 데이터 업데이트 필요 | API 비용·한도 관리 필요 |
| **적합 사례** | 미술관·전시 등 고정 데이터 | 뉴스, 최신 전시, 트렌드형 정보 |

> **혼합형 (RAG + Web)**
 1. 내부 DB 검색 : 관련 문서 있을 경우, 그대로 사용
 2. 검색 실패 → 웹 검색 API 호출
 3. (LLM) 두 정보 종합하여 답변 생성

#### **DB**

  정형 DB(SQL) + 비정형 벡터 DB
    
  | 구분 | 역할 | 예시 |
  | --- | --- | --- |
  | **작품 메타데이터 DB** | 그림 제목, 작가, 연도, 설명 등 정형 데이터 저장 | `"모나리자", "레오나르도 다빈치", 1503, "초상화..."` |
  | **지식검색용 벡터 DB (RAG용)** | 작품 설명, 문서, 해설문을 임베딩(수치화)해서 의미 기반 검색 | `"모나리자의 미소 의미" → 유사한 문장 검색` |
    
- 정형 데이터
      
    SQLite (로컬 개발용) → PostgreSQL (운영 배포용) 확장
      
    | 항목 | 선택 기준 | 추천 |
    | --- | --- | --- |
    | **데이터 크기** | 작품 수가 수백~수천 개 수준 | SQLite / PostgreSQL |
    | **팀 규모** | 1~4명 팀, 간단한 로컬 or 클라우드 배포 | SQLite로 시작 |
    | **동시 접속/확장성** | 여러 사용자, 클라우드 서버 운영 | PostgreSQL / MySQL |
    | **AI 연동 용이성** | Python(FastAPI)와 호환성 | PostgreSQL (SQLAlchemy 지원 좋음) |
        
    | 항목 | SQLite | PostgreSQL |
    | --- | --- | --- |
    | 데이터 성격 | 정적 / 변경 적음 | 동적 / 변경 많음 |
    | 위치 | 앱 내부 | 서버 |
    | 예시 데이터 | 작품 제목, 작가명, 설명 요약 | 전시 일정, 사용자 로그 |
    | 네트워크 필요 | ❌ 오프라인 가능 | ✅ 필요 |
    | 추천 용도 | 빠른 조회, 기본 정보 | 최신 정보, 다중 사용자 관리 |
    | AI 도슨트에서 | 작품 기본 DB | 전시 일정 및 서버 연동 |
    
- 비정형 데이터
        
    작품 설명문, 해설문 FAISS로 임베딩 저장
        
    | 항목 | 설명 | 추천 예시 |
    | --- | --- | --- |
    | **검색 속도** | 문서 수 적음(100~1000개 수준) | FAISS (로컬 저장형, 빠름) |
    | **클라우드 서비스 통합** | 백엔드가 AWS / GCP일 경우 | Pinecone, Weaviate |
    | **무료/오픈소스 여부** | 연구/졸업작품 용도 | FAISS or ChromaDB |
    | **LLM 연동 호환성** | LangChain 등 지원 | FAISS / Chroma 모두 OK |
    
요약
    
  | 구분 | 용도 | 저장 내용 | 대표 예시 |
  | --- | --- | --- | --- |
  | **① SQLite / PostgreSQL** | “정형 데이터 저장” | 작품 제목, 작가, 연도, 이미지 경로 등 | `"모나리자", "다빈치", 1503` |
  | **② FAISS (벡터 DB)** | “설명문 의미 검색” | 작품 해설, 비평문, 큐레이터 설명 등 | `"모나리자의 미소는 신비로움의 상징이다."` |
  | **③ LangChain + LLM** | “두 DB의 데이터 활용” | 질문 분석 + 정보 조합 + 답변 생성 | 질문: “이 그림 의미 뭐야?” → 답변 생성 |

#### **웹 검색**

  필요 시 추가 정보 제공
    
  | 이유 | 설명 |
  | --- | --- |
  | **최신 정보 반영** | 새로운 전시회, 작가 소식 등 DB에 없는 정보 확보 |
  | **DB 보완** | 내부 데이터가 부족한 질문에 대응 가능 |
  | **유연성** | “이 작가 다른 작품 뭐 있어?”처럼 외부 참조 필요한 질문 처리 가능 |
    
- 웹 검색 API
        
    | 이름 | 제공사 | 장점 | 단점 | 한글 지원 | 비고 |
    | --- | --- | --- | --- | --- | --- |
    | **Bing Web Search API** | Microsoft Azure | 빠름, LLM과 호환성 | 월 무료쿼터 1000건, API 키 필요 | ✅ 매우 좋음 | LangChain 내장 지원 |
    | **Wikipedia API** | Wikimedia | 무료, 빠름 | 최신 전시 정보 부족, 문장 짧음 | ✅ | 내부 지식용으로 추천 |
        
    | 목적 | 추천 API | 이유 |
    | --- | --- | --- |
    | 작품 기본 정보 / 작가 설명 | **Wikipedia API** | 빠르고 무료, 도메인 지식 신뢰도 높음 |
    | 실시간 최신 정보 검색 | **Bing Web Search API** | 뉴스, 전시 정보 검색에 강함 |
        
    Bing Web Search 예시 (Python)
        
    ```python
    import requests
        
    def bing_search(query):
        api_key = "YOUR_BING_API_KEY"
        url = "https://api.bing.microsoft.com/v7.0/search"
        headers = {"Ocp-Apim-Subscription-Key": api_key}
        params = {"q": query, "mkt": "ko-KR", "count": 3}
        response = requests.get(url, headers=headers, params=params)
        data = response.json()
        results = [item["snippet"] for item in data.get("webPages", {}).get("value", [])]
        return results
    ```
      
    Wikipedia API 예시
        
    ```python
    import requests
      
    def wiki_search(query):
        url = f"https://ko.wikipedia.org/api/rest_v1/page/summary/{query}"
        response = requests.get(url)
        if response.status_code == 200:
            data = response.json()
            return data.get("extract", "결과 없음")
        return "정보를 찾을 수 없습니다."
    ```
        
    구현 전략 예시 (하이브리드 검색)
        
    ```python
    def hybrid_search(query):
        # 1️⃣ 내부 DB 검색
        results = search_local_db(query)
        if results:
            return results
            
        # 2️⃣ Wikipedia 우선
        wiki_result = wiki_search(query)
        if wiki_result and wiki_result != "정보를 찾을 수 없습니다.":
            return wiki_result
            
        # 3️⃣ Wikipedia에 없으면 Bing으로
        bing_results = bing_search(query)
        if bing_results:
            return " ".join(bing_results)
          
        return "관련 정보를 찾을 수 없습니다."
    ```

#### <span style="background-color: #b6d3f6;">**LangChain 통합**</span>

  | 항목 | 설명 |
  | --- | --- |
  | **통합성** | 여러 검색·DB·API 하나의 흐름으로 관리 |
  | **자동화** | 어떤 Tool 쓸지 LLM이 판단 (Agent 구조) |
  | **지식 확장성** | 내부 + 외부 정보 모두 활용 |
  | **모듈성** | “이미지 인식”, “전시 안내 지도” 등 Tool 추가 가능 |
  | **개발 간결화** | FastAPI에서 LangChain 객체 한 번만 호출하면 전체 작동 |
    
  코드 예시
    
  ```python
  from langchain.agents import initialize_agent, AgentType
  from langchain.tools import Tool
  from langchain.chat_models import ChatOpenAI
  from langchain.chains import SQLDatabaseChain
  from langchain.sql_database import SQLDatabase
  from langchain.vectorstores import FAISS
  from langchain.embeddings import OpenAIEmbeddings
  from langchain.utilities import WikipediaAPIWrapper, BingSearchAPIWrapper
    
  # 1️⃣ 기본 모델
  llm = ChatOpenAI(model="gpt-4o-mini")
    
  # 2️⃣ DB 검색
  # SQLite (작품 기본 정보)
  sqlite_db = SQLDatabase.from_uri("sqlite:///museum_artworks.db")
  sqlite_chain = SQLDatabaseChain.from_llm(llm, sqlite_db, verbose=True)
    
  def search_sqlite(query: str):
      """
      SQLite 예시 쿼리:
      - '모나리자의 작가가 누구야?'
      - '수련의 제작 연도를 알려줘'
      """
      return sqlite_chain.run(query)
  
  # PostgreSQL (전시 일정, 장소 등)
  pg_db = SQLDatabase.from_uri("postgresql://user:password@localhost:5432/museum_info")
  pg_chain = SQLDatabaseChain.from_llm(llm, pg_db, verbose=True)
    
  def search_postgres(query: str):
      """
      PostgreSQL 예시 쿼리:
      - '다빈치 전시회가 언제 열려?'
      - '루브르 박물관에서 열리는 전시 알려줘'
      """
      return pg_chain.run(query)
    
  # FAISS (작품 설명문)
  embeddings = OpenAIEmbeddings()
  vector_db = FAISS.load_local("artworks_faiss", embeddings)
  retriever = vector_db.as_retriever(search_type="similarity", k=3)
    
  def search_faiss(query: str):
      docs = retriever.get_relevant_documents(query)
      joined_docs = "\n".join([d.page_content for d in docs])
      return f"[작품 해설문]\n{joined_docs}"
  
  # 3️⃣ 위키피디아 & Bing 툴
  wiki = WikipediaAPIWrapper()
  bing = BingSearchAPIWrapper(api_key="YOUR_BING_KEY")
    
  tools = [
      Tool(name="SQLiteDB", func=search_sqlite, description="작품 기본 정보 검색"),
      Tool(name="PostgreSQLDB", func=search_postgres, description="전시 일정/장소 검색"),
      Tool(name="FAISSDB", func=search_faiss, description="작품 설명 검색"),
      Tool(name="Wikipedia", func=wiki.run, description="작품/작가 기본 정보 검색"),
      Tool(name="BingSearch", func=bing.run, description="최신 전시 정보 검색")
  ]
    
  # 4️⃣ Agent 초기화
  agent = initialize_agent(
      tools=tools,
      llm=llm,
      agent_type=AgentType.ZERO_SHOT_REACT_DESCRIPTION,
      verbose=True
  )
    
  # 5️⃣ 실행
  question = "모나리자는 현재 어디에 전시되어 있어?"
  response = agent.run(question)
  print(response)
  ```

  FastAPI 연결 시
  
  ```python
  @app.post("/ask")
  async def ask(request: Request):
      question = (await request.json())["question"]
      answer = agent.run(question)
      return {"answer": answer}
  ```

  | 구성요소 | LangChain에서 담당 | 역할 |
  | --- | --- | --- |
  | **DB** | `SQLDatabaseChain` | 작품 기본 정보 조회 |
  | **FAISS 벡터DB** | `VectorStoreRetriever` | 설명문 의미 검색 |
  | **Wikipedia API** | `WikipediaAPIWrapper` | 일반 지식 보완 |
  | **Bing Search API** | `BingSearchAPIWrapper` | 최신 전시 정보 |
  | **LLM** | `ChatOpenAI` | 답변 생성 |
  | **Agent** | `initialize_agent()` | 위 요소들을 자동 조합 |
  | **결과** | `/ask` API로 전달 | 앱에서 음성 응답 출력 |

### ④ 답변 생성

검색 결과 기반으로 문장 자연스럽게 구성

e.g. LLM 기반

```python
from openai import OpenAI
client = OpenAI()

prompt = f"""
너는 박물관 도슨트야. 아래 정보로 관람객에게 친절히 설명해줘.

작품 정보:
{retrieved_text}

사용자 질문: {user_question}
"""

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": prompt}]
)

answer = response.choices[0].message.content
```
